# Editors (autosave frame)

Reference: `src/components/editor/editor-frame.tsx`, `src/hooks/use-autosave.ts`, `src/hooks/use-undo-history.ts`. The song editor (`src/features/songs/song-editor.tsx`) is the first editor on the frame; the setlist editor adopts it when it is rebuilt.

- **No Save button.** Every change saves as it goes. The draft lives in `useUndoHistory` (client state for the form being edited, seeded from the item's query); the server copy stays in TanStack Query.
- **`useUndoHistory(initial)`** keeps the last 60 snapshots. `set(next)` pushes a step, `undo()` steps back, `canUndo` drives the button. Pass `{ coalesceKey: 'title' }` while typing so one field counts as one step, and call `endCoalesce()` on blur.
- **`useAutosave({ value, save })`** waits until `value` has been still for `delayMs` (800), then calls `save(value)` once at a time and returns `status` (`saving`, `saved`, `error`, `paused` while `enabled` is false), `flush()` and `retry()`. Wire `save` to a mutation's `mutateAsync` against the existing PUT update endpoint (`updateSong`, `updateSetlist`), and invalidate or set the item's query data in that mutation's `onSuccess`. The value on mount counts as saved, so opening an editor never saves. Send the whole draft each time; the update endpoints replace the item.
- **`EditorFrame`** is the one frame: `names` (the borderless title input and its subtitle), Undo, `actions` (a mode switch), Done, `chips`, and on phones a glass save bar in place of the header buttons. It hides the phone tab dock through `useEditingMode()` (an `editing` class on `<html>` that `AppShell` reads) and handles Ctrl/Cmd+Z outside text fields and Ctrl/Cmd+S ("Everything saves as you go").
- **Done** is `onDone`: `await flush()`, then navigate to the item (`/songs/$songId`, `/setlists/$setlistId`). Do not navigate when `flush()` resolves `false`.
- **Chips** are `EditorChip` (`label`, `value`, popover content, width through `contentClassName`) inside the frame's `chips`. The Saving / Saved chip sits at the end of the row on wide screens and under the title on phones; the frame places it.
- **Reordering** uses `ReorderList`: `renderItem(item, index, handle)` puts the grip where the row wants it. Dragging reorders live; arrow keys on the focused grip move the row and announce "X moved to position N of M". Give `getLabel` the item's visible name. `ReorderList` also serves reorders that are not saved to the server: the setlist reader's "Edit order" (`src/features/setlists/musician-view/local-order.ts`) keeps a per-device song order in localStorage (`setlist-order:<setlistId>`, a Zod-parsed array of song ids) and `reconcileOrder` drops ids that left the setlist and appends new ones.
- **Tests:** `useAutosave` tests use `vi.useFakeTimers()` because the debounce is the behaviour under test; everything else still avoids timers.
- **The draft is not the wire shape.** The song editor keeps a `SongDraft` (`song-draft.ts`: sections as `{ id, label, lines }`, the key as a `MusicKey`) and turns it into the update body with `toSongInput`. Pass `isEqual` to `useAutosave` that compares what would be sent (`sameInput`), so undoing back to the saved state is not a change, and `enabled: false` while the draft is something the server refuses (no title, no lyrics); Done then toasts what is missing instead of navigating.
- **Autosave writes the detail query, not the list.** On success the mutation merges the sent fields into the item's detail query with `setQueryData` and only marks the list queries stale (`['songs', 'search']`), so a save every few seconds never refetches the page being edited.
- **Stored text is parsed into blocks and back.** `parseSections` / `serializeSections` turn ChordPro (`{Verse 1}` headers, `[G]` chords) into editable sections and round-trip canonical text unchanged; per-line chord moves go through `parseLine` / `placeChord`. Keep new storage-format logic in that file, with a round-trip test.
- **Popovers near the screen edge** pass `collisionPadding` so they stay inside a 390 px viewport; `EditorChip` does this already.
