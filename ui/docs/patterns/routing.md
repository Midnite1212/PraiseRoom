# Routing

Reference: `src/routes/`.

- **File-based routes.** `pnpm dev` and `pnpm build` regenerate `src/routeTree.gen.ts`; commit it, never edit it.
- **Signed-in pages** live under `src/routes/_app/`. The `_app` layout's `beforeLoad` ensures the session and redirects to `/login?redirect=<current href>` when signed out, then returns `{ session }` into route context.
- **Signed-out pages** (`login.tsx` is Sign in, `sign-up.tsx`, `forgot.tsx`, `check-email.tsx`, `reset.tsx`) sit beside `_app` and use `AuthLayout` (no rail or tab bar). Sign in and sign up redirect a signed-in user with `redirectIfSignedIn` (`features/auth/signed-out.ts`) to `toSafeRedirect(search.redirect)`; forgot, check-email and reset stay open to everyone. `/reset` reads the `token` (or `error`) search param Better Auth adds to the password-reset redirect; `check-email` reads the address from `sessionStorage` (`check-email-state.ts`), not the URL. Always pass redirect targets through `toSafeRedirect`, which only allows same-origin paths.
- **Account pages** (`/account`, `/account/password`) are `_app` routes; Settings and the profile menu link to Account, and each has a back button (`AccountBack`: top-bar chevron on phones, "‹ label" on wide screens).
- **Access types:** gate editor or admin pages in that route's `beforeLoad`, using the session from context (for example `canWriteSongs(context.session)`), and redirect or throw `notFound()`. This is UX only; the server enforces access.
- **Search params:** declare them with a Zod schema in `validateSearch`, using `.default(...)` so links can omit them and `.catch(...)` so a bad URL falls back instead of erroring. Read them with `Route.useSearch()`; change them with `Route.useNavigate()({ search })`.
- **Selection as a search param:** a picked list row (`set` on `/setlists`) lives in the URL and is ignored on phones; change it with `replace: true`. Router scroll restoration scrolls to the top on every navigation, so a selection change passes `resetScroll: false` to keep the list where it is (`selectSong` in `src/routes/_app/songs/index.tsx`).
- **List and pane:** on wide screens a list page can open a record beside the list in place (`/folders?folder=<id>`, `src/routes/_app/folders/index.tsx`): the selection is a validated search param so it survives reload and back, rows are `<Link search>` rather than links to the record's page, the pane renders the same feature component the record's route renders (`FolderDetail`, with `inPane`) inside a `Suspense`, an id that is not in the list is ignored, and the close button and Esc (a window `keydown` listener that skips inputs, dialogs and menus) clear the param and focus the row. Phones ignore the param and keep list then page.
- **Data:** `loaderDeps: ({ search }) => search` plus a `loader` that calls `ensureQueryData` (see `data-fetching.md`). Give slow routes a `pendingComponent` skeleton.
- **Record slugs:** song, setlist, and folder paths are `<name>-<urlKey>` (`/songs/amazing-grace-k3x9p2`, `/setlists/sunday-service-2026-10-26-a7m4qd`), built with `songSlug`, `setlistSlug`, and `folderSlug`. Links always go straight to the slug, never through a redirect. Only the six-character `urlKey` finds the record and the name part is not checked, so a link made before a rename still opens. The loader calls `ensureFromSlug` (`src/lib/ensure-or-not-found.ts`) and returns `{ urlKey }`; the component reads with `useSuspenseQuery(<resource>QueryOptions(urlKey))`, and detail caches are keyed by `urlKey`. Reference: `src/routes/_app/setlists/$setlistSlug.tsx`.
- **Missing records:** for a detail route (`/setlists/$setlistSlug`), the loader turns an `ApiError` 400 or 404, or a param with no url key, into `throw notFound()`, so a bad link shows the not-found screen instead of the error screen.
- **Action links:** a link that does something when opened (`/join/$token`) sits under `_app` so signed-out visitors go through the login redirect first; its `beforeLoad` makes the call, throws `redirect` on success, and returns a failure key the component renders, so a failed link shows its own error state instead of the error screen.
- **Edit pages** sit beside the record's view with a trailing underscore so they don't nest under it (`$setlistSlug_.edit.tsx` → `/setlists/$setlistSlug/edit`). Their loader checks the same rule the UI uses to show the Edit button (`canEditSetlist`) and redirects back to the view when it fails.
- **Keyboard shortcuts** (such as ← and → to change songs) are a window `keydown` listener in an effect that ignores inputs, selects, and editable elements, and changes search params with `replace: true` so they don't flood history.
- **Links:** use `<Link to="/songs">` (type-checked). For shadcn buttons, wrap with `<Button asChild><Link …/></Button>`.
