# Components and styling

The visual design is the app-pages mock (`design-poc/app-pages.html`): black and white with one accent, frosted Liquid Glass for anything that floats, rows on bare ground, and liquid motion.

- **Start from what exists.** Check `src/components/primitives/` and `src/components/page/` first, then `src/components/ui/` (shadcn), then the shadcn registry. Compose those in feature components instead of building controls from `div`s; anything a second screen repeats becomes a primitive.
- **shadcn files carry the design.** `button`, `dialog`, `alert-dialog`, `popover`, `dropdown-menu`, `input`, `select`, `switch`, `toggle`, and `sonner` are restyled in place, so every screen gets the same controls. Keep further edits small and note them in the PR, since `shadcn add --overwrite` would undo them.
- **Variants:** use `cva` (as shadcn does) for components with variants, and `cn()` from `@/lib/utils` to merge classes. `Button` sizes: `default` (44px, 40px on wide, 15px text), `icon` (44px on phones, 40px on wide; a `glass` icon button stays 40px), `sm` links (44px tap height on phones, with a negative margin so rows do not grow) and `compact` (36px, for `exit` pills). Segmented controls are 36px at `sm` and `md`. Removing an item from a list (a folder member, a setlist from a folder, a song from a setlist, a section in the song editor) uses `RemoveIcon` (`components/primitives/pixel-icons.tsx`, a minus in a ring); close buttons keep `Close`. Type scale tokens (`text-page-title` 28px, `text-pane-title` 24px, `text-card-title` 20px, `text-ui` 15px buttons and nav) live in `src/styles.css`; use them instead of arbitrary sizes. `Button` variants: `default` (the ink capsule, the one filled button), `secondary`, `ghost`, `glass` (a floating glass circle or capsule), `link` (accent text), `destructive`, `destructive-solid`, `exit` (the glass capsule for Leave, Delete and similar exits: a whisper of red at rest, full red on hover and focus; use `size="compact"`). A folder's page is the hero (sleeve, name with an inline rename pencil, people strip that opens the Members dialog on every width), an Add setlists / Add people row, its setlists (`orderFolderSetlists`: upcoming soonest first, then undated, then past newest first) and an Exits section of `exit` pills. Leaving or deleting ends in `goneToast` (a red-trash toast).
- **Tokens only:** colours, radii, and fonts come from the CSS variables in `src/styles.css` through Tailwind classes. Add a new token for both `:root` (light) and `.dark` before using a new colour.

  | Token                                             | Tailwind                                       | Use                                                   |
  | ------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------- |
  | `ground` / `ground-lift`                          | `bg-ground`                                    | The page, and the soft wash of light at its top       |
  | `ink`, `ink-2`, `ink-3`                           | `text-ink`, `text-ink-2`, `text-ink-3`         | Primary, secondary, and tertiary text                 |
  | `brand`                                           | `text-brand`, `bg-brand`                       | The accent; `chord`, `ring`, and `pixel-on` follow it |

  | `pixel-off` / `pixel-played` / `pixel-on`         | `bg-pixel-*`                                   | Setlist progress pixels                               |

  | `cover`, `cover-light`, `cover-soft`, `cover-dim` | `bg-cover-*`                                   | Folder sleeve equaliser                               |

- **Liquid fills:** hover and selected states are a drop of glass. `hover:liquid-hover` replaces `hover:bg-fill-hover` and `liquid-on` (also `aria-pressed:liquid-on`, `data-[state=on]:liquid-on`) replaces `bg-fill-on`; each utility sets the background and an inset edge from `--liquid-hi`, `--liquid-lo` and `--liquid-rim` (both themes). The highlight follows a mouse through `--mx` and `--my`, written by the one delegated listener in `src/lib/liquid-pointer.ts` (started in `main.tsx`; mouse only, off under `prefers-reduced-motion`), so a new control needs only the class. A selected row that can also be hovered takes both (`liquid-on hover:liquid-on`). Leave `.glass` buttons, danger rows and table cells on the flat fills: the utilities replace `box-shadow`, which glass uses for its drop shadow, and a table cell cannot share one highlight across its row. `fill-press` stays the pressed state.
- **Lit icons and state colours:** `lit-icon` on a control makes the pixel icon inside it turn the accent and glow on hover (mouse only; not while disabled, current or pressed); `Button` (ghost, outline, secondary, glass, link), `MenuRow`, `MenuTile` and the nav links carry it, so a new control with an icon takes the class. `lit-icon-danger` is the red form for controls that remove or end something (`Button variant="exit"`, `MenuRow tone="danger"`), which also rest in `text-danger-quiet`: Sign out, the swipe Delete action, Leave and Delete folder. Only colour and filter change; motion is separate. `withPixelMotion(Icon, recipe)` (`components/primitives/pixel-motion.tsx`) turns a pixel icon into one that moves while its `lit-icon` or `lit-icon-danger` control is hovered or keyboard-focused: `src/lib/pixel-motion.ts` rasterizes the icon's path onto the 24-unit grid once, a recipe (`nudge`, `ripple`, `wave`, `bars`) returns up to seven frames, and the `.pixel-strip` CSS steps through them side by side with one transform, so a resting icon costs nothing and nothing runs in JavaScript per frame. Define the moving icon at module scope (as `NAV_ITEMS` does), never inside a component. `text-ok` (`--ok`, both themes) means done: the Saved check and the success toast. Removals toast through `goneToast(message, options?)` (`components/primitives/gone-toast.tsx`, a red trash icon) rather than `toast.success`; `toast.success` is the green check.
- **Glass:** `.glass` (in `src/styles.css`) is the frosted surface: backdrop blur (12px, 220% saturate, 1.08 brightness), tint and a top-left `--glass-sheen` highlight on `::after`, a flat `--rim-edge` hairline on `::before`. `--sheen` is the refraction pointer glow (a 0–1 number), not the frosted sheen. Add `glass-over` for glass over moving content, `glass-strong` for sheets, and set the corner with `[--glass-r:24px]`. A glass element's content must not scroll the host itself; scroll an inner element (see `DialogContent`). Settings → Glass can switch Chromium browsers to refraction (`src/lib/liquid-glass.ts`): it puts `.refract` on `<html>` and gives every `.glass` an SVG filter sized to it, so new glass needs no extra wiring.
- **Wide vs phone:** the `wide:` variant (`min-width: 768px` and `min-height: 600px`, no orientation test) switches to the wide layout, so tablets and half-screen desktop windows get it while a phone turned sideways keeps the phone layout. The query is defined once as `WIDE_QUERY` in `src/hooks/use-wide.ts`; the `@custom-variant wide` in `src/styles.css` repeats that text and a test keeps them equal, so change both together. Never use Tailwind's own `sm:`, `md:` or `lg:` to mean phone versus wide; use `wide:`. `useIsWide()` is the same query for code that must render differently (a table instead of rows, a popover instead of a sheet). Anything that puts a second column beside the page (Settings' preview, the Songs preview, the Setlists calendar column and preview, the Folders pane, Home's two columns, the split reader and its song sidebar) uses the `roomy:` variant or `useIsRoomy()` (`ROOMY_QUERY`, 1100px wide and 600px tall, kept equal to the CSS the same way); between 768 and 1100px those pages keep one column. That band is `compact` (`COMPACT_QUERY`, `useIsCompact()`, the `compact:` variant, all kept equal to the CSS the same way): the Setlists calendar is hidden, the Setlists side column and the setlist editor's Add songs panel stack under the list, and the panes that sat beside a list (Songs preview, Setlists preview, an open folder) become a slide-over. A pane that does this takes `SLIDE_OVER_CLASSES` and `SLIDE_OVER_CLOSE_CLASSES` (`src/components/page/slide-over.ts`: a fixed glass panel over the right of the page, `compact:` only) and its page calls `useSlideOver(isOpen, onClose)`: `close` waits for the exit animation (`animate-over-in`/`animate-over-out`, which `prefers-reduced-motion` shortens to 1ms), the panel takes focus when it opens and focus returns to what opened it, and Esc and the close button both call `close`. Below 1100px the rail stays folded and its toggle is hidden.
- **Sheets, menus, panels:** `Dialog` is a sheet from the bottom on phones and a centred dialog on wide screens; pin its buttons with `DialogContent`'s `footer` so long sheets keep them in reach. `ActionMenu` (`⋯` menus) and `Panel` (reader panels) anchor to their button on wide screens and become sheets on phones.
- **Setlist menu and long-press:** `SetlistActionMenu` (`src/features/setlists/setlist-action-menu.tsx`) is a setlist's menu: an object header (date block, name, when and song count, the strip, close), Open / Share / Edit as `MenuTile`s, then `MenuRow`s for Duplicate, Add to a folder (`SetlistFolderDialog`, a `PickRow` list saved through `PUT /api/setlists/update`) and, for the creator or an admin, Delete; anyone else sees who made it. `ActionMenu` takes `open`/`onOpenChange` to be controlled and a `header` with a `MenuClose` button of its own. `SwipeRow` takes `onLongPress`: a 520 ms hold without moving 8 px shows a press (`data-holding`, a slight scale) and fires, swallowing the click that follows; a menu portaled out of the row never reaches its handlers. Leave and delete rows (`MenuRow tone="danger"`) use `text-danger-quiet` at rest and `text-destructive` on hover.
- **Icon-only buttons:** give a button that is a bare icon a Button icon size (`icon`, `icon-lg`, `dock`, `dock-step`), never `size="default"` with `px-0` and a width: the default size's `has-[>svg:first-child]:pl-3.5` outranks `px-0` and shifts the icon 7px. `Fab` renders into `body` (a page's entrance animation moves its wrapper, and a moving ancestor becomes the containing block of a fixed child). `DialogContent` calls `useKeyboardInset` (`src/hooks/use-keyboard-inset.ts`), which publishes the on-screen keyboard's height as `--kb` so phone sheets sit above it. `LoadingStatus` (`components/page/loading-status.tsx`) is the loading line for searches: show it while a request is in flight and the empty state only once one has finished.
- **Motion:** `ease-out` and `ease-liquid` (a slight overshoot) are the two easings; `animate-sheet-in`, `animate-pop-in`, `animate-view-in`, and `animate-spin-slow` are the shared animations. `prefers-reduced-motion` turns them off globally.
- **Fonts:** `font-sans` (UI), `font-mono` (keys, dates, counts, chords), and `font-lyrics` (lyrics) map to `--typeface-*` variables with Traditional Chinese fallbacks (`--typeface-han`). The Settings page's font choice (`useTypeface()`, `src/lib/typeface.ts`) sets `data-typeface` on `<html>`; the accent choice (`useAccent()`, `src/lib/accent.ts`) sets `data-palette`. IBM Plex Sans and IBM Plex Mono are the defaults (`--typeface-mono` stays Plex Mono for every choice); Geist, Hanken Grotesk, Pixel, Mono and System are alternatives, and a stored `geist` moves to Plex once (`src/lib/typeface.ts`). Fonts are self-hosted from Fontsource packages imported in `main.tsx`.
- **Lyrics size:** `text-lyrics` reads `--lyrics-size`, which `data-lyrics-size="sm|md|lg|xl|2xl"` on the reading sheet sets. The reader picks the size with `useLyricsSize()` (`src/features/reader/lyrics-size.ts`), stored per device.
- **Theme:** `next-themes` sets the `dark` class on `<html>`; use `dark:` variants only when a token can't express the difference. `ThemeChoice` and `LanguageChoice` (`src/components/layout/preference-choices.tsx`) are the one way to pick them.
- **Icons:** `pixelarticons/react`, sized `size-icon` (18px, 16px on 2× screens) unless a component sizes them. Icon-only buttons need an `aria-label` from `t()`.
- **Layout:** `AppShell` owns the chrome: the fixed rail on wide screens, 232px open and a 72px icon strip when folded (the choice is `useRail`, `src/lib/rail.ts`, per device; below 1100px (not `roomy`) the rail stays folded whatever the choice and its toggle is hidden; page content is capped at `calc(1272px - var(--rail-w))`, so it widens when the rail folds; the toggle sits in the brand row, revealed on hover when folded, and ⌘\ or Ctrl+\ flips it; the shell sets `data-rail` and `--rail-w` on its wrapper, and rail pieces hide their text with `group-data-[rail=folded]/rail:hidden` and take a `title` when folded) (the brand on the ground in a `--head-h` band shared with the page title, the pages island, a Next up card from `NextUpIsland` on every page except Home and Setlists, then you), the top bar and tab dock on phones, and the page frame. `BrandMark` takes a 28px box and draws a 40px logo with the accent glow. Pages start with `PageHeader` (its actions show on wide screens; phones get a `Fab`), then `Finder` (pass `sticky={false}` inside a split layout), `GroupTitle`, and rows (`listRowClasses`, `RowText`). Page headers carry no subtitle (Home keeps its date); the first `GroupTitle` on a page takes `first` for a tighter top margin, and its `hint` is a quiet right-aligned note such as the sort order. Rows are 64px tall with a 12px gap; `LIST_COMPACT_CLASSES` removes the gap between rows for reference lists such as played setlists. A page that needs the phone top bar's back button or menu renders it with `AppBarSlot`. Routes with `staticData: { chrome: 'reader' }` get no shell and render `ReaderLayout` instead.
- **Per-device choices** (lyrics size, Lyrics/Chords, 1-4-5/A-B-C, sharps and flats, accent, glass) are made with `createStoredChoice` (`src/lib/stored-choice.ts`). Read one through a hook-named alias (`const useAccent = choice.use`), never `choice.use()` inline: the React Compiler only treats `use*` names as hooks and would otherwise memoize the call away.
- **Set-status primitives** (`src/components/primitives/`): `set-status.ts` decides a setlist's status (`next` = the soonest set dated today or later across the whole list, `up`, `past`, `undated`) with `nextSetlistId(setlists, now)` and `setStatus(setlist, nextId, now)`; compute the id once from the full list, never from a filtered one. `DateBlock` takes that `status` and lights up (the accent fill) only for `next`; Home's `NextUp` and the Setlists `NextSetCard` pass `next` so the next set's date keeps the accent. `whenLabel(date, now, language)` gives "today", "tomorrow", "in 3 days", "3 days ago". `SetStrip` (a strip of light, one 7px square per song, with a screen-reader label), `TempoMeter` (four bars, the fastest of a song's tempos), `KeyChip`, `KeyTile` (key over time signature, leading a song row) and `AuthorLine` (an 18px avatar and a name) are the shared pieces the Songs, Setlists, Home and Folders pages use for the same information; reuse them instead of drawing keys, tempos or authors again. `SetlistRow` shows the strip, the author line for a shared set, and every folder tag except `hideFolderId` (a folder page passes its own id); `ManagedSetlistRow compact` renders `PlayedSetlistRow`, the one-line form for the collapsible Played group. On phones with no filter the Setlists page leads with `NextSetCard` (`groupSetlists(..., { leadWithNext: true })` splits it out of Coming up, which then reads Then).
- **Select-to-preview and day linking (Setlists, wide):** a click on a row picks it (`?set=<id>`, wide screens only) and shows `SetlistPreview` in the sticky side column above `SetlistCalendar`; double-click or Enter opens the setlist, Space picks, ↑/↓ moves and Esc closes. Rows and the calendar read `SetlistListContext` (`setlist-list-context.ts`) for the picked id and the lit day; hovering or focusing a row or a calendar day lights every element with the same date (`bg-fill-on`). Outside that page the context is idle and rows are plain links. Calendar dots take the status colour (`next`, `up`, `past`) from `set-status`.
- **Home:** `NextUp` (`src/features/home/next-up.tsx`) is the whole-card link to the next set: the title's `after:` overlay covers the card (hover lifts it 2px and swaps to the over-glass fill, focus shows an accent outline, wide screens fade in an Open hint), the corner button copies the public link, and the songs list the set's keys. Below it Home reads Then, Your folders (`FolderRow`), and Recently added (`SongRows` fed by `recentSongsQueryOptions`, which asks `/api/songs/search` for `sortBy=recent`: newest `createdAt`, then id).
- **Reading a song:** `SongReader` (`src/features/reader/song-reader.tsx`) is the one reading sheet (song view, setlist view, public setlist view, editor previews): title with ⓘ, artist with the key and lyric columns, then the lyrics. `ReaderLayout` is the full-screen frame around it; `MusicianView` (`src/features/setlists/musician-view/`) adds the setlist sidebar or song row, progress pixels, and the Up next dock (on the last song its pill reads "Previous" with the song before it, which the ‹ button goes to; "End of the set" only for a one-song set).
- **Auto-scroll:** `useAutoScroll(songKey)` (`src/features/reader/auto-scroll.ts`) is called once by each reader view (`SongView`, `MusicianView`, so the public link too) and passed down as `auto`. It runs `createAutoScroller` (a `requestAnimationFrame` loop that carries the fractional pixels between frames and caps a long frame gap) on the page scroll, at the per-device `useScrollSpeed()` (Slow 16, Medium 28 default, Fast 44 px/s; a speed change applies on the next frame). It stops itself at the end of the song with an "End of the song" toast, when the reader scrolls by hand (wheel, a touch drag, the scroll keys, the scrollbar; taps and anything inside a button, link or dialog do not count), and when `songKey` changes. `prefers-reduced-motion` does not change it: the reader starts it, can pause it, and the speeds are what a band reads by. `AutoScrollButton` is the glass play/pause button: `placement="top"` sits after the modes in `ReaderLayout`'s `auto` slot on wide screens, `placement="dock"` follows Aa in the phone dock. `ScrollSpeedRow` (the tempo-icon segment and the note naming where the button is) shows in the Aa tray only for a view that passes `auto`, so editor previews have none. The Settings page's Auto-scroll speed row reads the same `useScrollSpeed()`.
- **Split reader (wide):** `MusicianView` shows two songs side by side when `useReaderLayout()` (`musician-view/split-panes.ts`, `split` by default, `one` otherwise, per device) is `split`, the screen is wide and roomy and the set has more than one song; the One | Split icon segment (`ViewOneIcon`, `ViewSplitIcon` in `reader/view-icons.tsx`, drawn on the pixelarticons grid like `SidebarIcon`) sits in the top row's actions and is hidden otherwise. `ReaderLayout isSplit` swaps the page-scrolling `main` for a fixed two-column stage, and `SplitView` fills it: each pane scrolls on its own and has a chooser (`Panel` of `SetlistPickRows`: "Play now" on the left, "Show beside it" with "Next song (follow the set)" on the right). `rightPane`, `pinAfterPick` and `pinAfterMove` decide the right song from the local order (the left pane's index and an optional pinned song id, held in `MusicianView` state, not stored); past the last song the right pane reads "End of the set". The sidebar rows take `isShown` and `tag` ("Pinned"). `useAutoScroll(songKey, scrollTarget)` scrolls the left pane's element instead of the page; the panes pass `pane` to `SongReader` for a smaller title and their own title id. Keys, capo (`useSongCapo` per pane) and chord settings apply to each pane.
- **Reading settings:** the sliders button in the reader's top row, at every width, in Lyrics and Chords modes (`ReadingSettings`, `src/features/reader/reading-settings.tsx`) opens a `Tray` (with a `description`, so it shows a head and a close button) of `SetRow`s for what is set once per device: Full or Simple chords, Colour chords with its four colour dots, sharps and flats (Auto, F#, Gb), theme and language (`ThemeChoice` and `LanguageChoice`, compact), then a More in Settings link (`showSettingsLink`; `MusicianView` hides it with `isPublic`, since the public link has no Settings page, and the theme and language rows are that page's only stand-in there). Show chords as lives in the key tray. The Keep screen awake row (a Switch, `useKeepAwake` in `keep-awake.ts`, on by default; its hint reads "On while this page is open" or "Not supported in this browser") follows the language row, and `ReaderLayout` calls `useWakeLock` so every reader, public link included, holds the lock while visible. A Present to TV row (a `SetRow` with `onClick`, so the whole row is a button) follows it, above the link when the view passes `present` (`songs`, `startIndex`, `onStart`, `onExit`; `SongView` and `MusicianView` do, the public link included). The row closes the tray, calls `onStart` (stops auto-scroll), asks for fullscreen (`enterFullscreen`, `fullscreen.ts`; refusal is fine) and mounts `Presentation` (`presentation.tsx`), which the settings own. `buildSlides` (`present-slides.ts`) makes a title slide per song then a slide per section; `Presentation` shows them full screen with the text fitted to the stage (`useFitText`: from 4.2% of the screen width, max 72px, down to 18px), a top bar (song, Show chords switch, Exit, "2/6 · Verse 1"), and a foot with the next line or song and a pixel per song. Arrows, PageUp/Down, space, enter and backspace, tap (left third goes back) and swipe move; c toggles chords; Esc or leaving fullscreen exits. Its keys are caught on `window` in the capture phase and stopped, because the setlist reader behind it also turns songs on the arrow keys; any full-screen layer over the reader does the same. On exit `onExit(songIndex)` lets the setlist view jump to the song stopped on. A new chord option adds a `SetRow` there with its own `createStoredChoice` in `chord-display.ts`, and reaches the chords through `LyricsSheet`'s props. Simple chords (`simplifyChord`, `src/features/chords/theory.ts`) keep only the root and minor, applied before transposing and numbering. Colour chords (`useColourChords`, a Switch row) tints each chord by `classifyChord` (`src/features/chords/chord-class.ts`): its root against the song's original key, so the colour survives transposing, Simple chords, and numbers. The hues are the `chord-four`, `chord-five`, and `chord-minor` tokens (1 is `chord`, others `ink-2`); an accent palette that sits near one swaps that token in `styles.css`. The capo is a `Stepper` row that is always in the key tray (`KeyPicker`), 0 meaning no capo; the fret is per song, held in the view beside the play key (`SongView`, `MusicianView`) and passed to `SongReader` and `KeyPicker` as `capo` and `onCapoChange`. Chords render as the shapes to play: `LyricsSheet` lowers the transposed letters by the fret and spells them by `shapeKey` (`key-spelling.ts`); numbers and colours do not move.
- **Chord settings:** the gear in chords mode (`ChordSettingsPanel`, `src/features/reader/chord-settings.tsx`) opens a `Panel` of `SetRow`s for per-device chord options (notation, Full or Simple chords, sharps and flats). A new chord option adds a `SetRow` there with its own `createStoredChoice` in `chord-display.ts`, and reaches the chords through `LyricsSheet`'s props. - **Settings page:** `SettingsPage` (`src/features/settings/settings-page.tsx`, given `session` by its route) is an account line (vinyl, name, email, role pill; no Account button until there is an account page to open), then Songs, Playing and Look and language as `SettingsGroup`s of `SettingsRow`s (`settings-group.tsx`: the heading is the shared `GroupTitle` and the one-line description under it is optional and not rendered when empty; label and hint in a 224px column and the control beside it on wide, under the label on a phone; `inline` keeps a switch beside its label), then a Sign out foot. Every row reads the stored choice the reader reads (`useLyricsSize`, `useChordNotation`, `useChordStyle`, `useAccidentals`, `useColourChords`, `useScrollSpeed`, `useKeepAwake`, `useTypeface`, `useAccent`, `useGlassStyle`), so the reader, Reading settings and this page stay in sync; a new per-device option adds a row here as well as in the tray. A control that stretches under its label on a phone takes `w-full wide:w-auto`. `Segmented` thumbs handle up to five options, so a longer list (Font, six) is a `ToggleGroup` of tiles. `ThemeChoice` takes `withIcons` for an icon before each name. `SettingsPreview` runs a short dummy chart (`settings.preview.chart`, `{Section}` and `[chord]` syntax, in the locale files) through `LyricsSheet` with the stored options, sized by `data-lyrics-size`; wide shows a titled card in a sticky side column, a phone shows one line sticky under the top bar (`useIsWide` picks where it renders).
- **Trays (Aa and key):** `Tray` (`src/components/primitives/tray.tsx`) is for controls you change mid-song: it never dims the page. Wide screens anchor it to its button as a popover; phones raise it above the dock with a grab handle, and a downward drag past 56px closes it (`--tray-drag` is set from the pointer handlers, as `SwipeRow` does with `--swipe`). Both are non-modal dialogs named by `title`: no focus trap and no scrim, Esc or a tap outside closes, so the song stays readable and scrollable. Use `Panel` for anything that should take over the screen. A tray that must close itself after an action takes `open` and `onOpenChange`; `AddToSetlist` (`src/features/setlists/add-to-setlist.tsx`, the reader's + and the song preview's button) does, closing once a setlist is picked. `ReadingPanel` (Aa: the lyric size with a tick meter, then the Scroll speed row and note when it gets `auto`) and `KeyPicker` (key, Show chords as, capo, reset link) are the two trays; `WideReadingControls` puts Aa in the wide top row. A control marked `data-keeps-tray` (the auto-scroll play button) can be pressed without closing the tray. A `Tray` with a `description` shows a title, that line and a close button above its controls (Reading settings); without one it has no visible heading.
- **Auth frame and account lists:** `AuthLayout` (`src/features/auth/auth-layout.tsx`) is the signed-out frame: brand, glass card, and on wide screens the chord-line art with a lit pixel strip beside it. Account lists (`ways to sign in`, `signed in on`) are `AccountItem` rows (icon tile, two lines, one action) inside a `SettingsGroup`. `KeyIcon` and `PhoneIcon` (`primitives/pixel-icons.tsx`) are drawn on the pixelarticons grid.
- **Toasts:** `toast.success` / `toast.error` from `sonner` for the result of a user action; an `EmptyState` for a list that failed to load.
- **Icon-only buttons name themselves:** `Button` with an `icon*` size and a string `aria-label` shows that label as a tooltip on hover and keyboard focus (500 ms delay, never on touch, closed while the button's own popover or menu is open) and drops its `title`. Pass `tooltip={false}` to opt out; do not wrap call sites in `Tooltip` by hand.
- **Loading and empty lists:** `LoadingStatus` is four running pixels plus three breathing skeleton rows (`compact` drops the rows); `EmptyState` takes `onClearSearch` and `onClearFilters` and shows Clear search and Clear filters only for the ones that are active. A dialog or sheet body fades at its bottom edge while more is below (`useMoreBelow`).
- **Saved chip:** one place on every page, the right end of the page header (`EditorFrame`, the account hero).
